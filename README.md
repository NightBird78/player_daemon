# Advanced WebSsocket Player Daemon

**Сучасний дистанційний аудіоплеєр** для Linux з підтримкою YouTube і локальних файлів.

Дозволяє керувати відтворенням музики з будь-якого пристрою (телефон, планшет, інший комп’ютер, навіть холодильник з браузером) через зручний веб-інтерфейс, не підходячи до основного ПК.

---

## Основна ідея

Хотілося мати можливість **"замовити" пісню** своєму комп’ютеру з телефону, не встаючи з дивана.  
Версія 2.0 отримала підтримку двох черг, локальних MP3-файлів, MPRIS-інтеграцію та покращений веб-інтерфейс.

### Ключові можливості

- **Дві черги з пріоритетами**:
  - **Active Queue** — пріоритетні треки (те, що треба зараз)
  - **Passive Queue** — фонова черга (фон, коли активна закінчується)
- Підтримка **YouTube** (посилання та плейлисти) через `yt-dlp`
- Підтримка **локальних файлів** (MP3 з читанням ID3-тегів)
- **WebSocket** керування в реальному часі
- **MPRIS** інтеграція (керування через KDE Connect, GNOME, polybar тощо)
- Інтерактивний веб-віджет з прогрес-баром, логами дій та відповідей
- Автоматичний перехід з Active → Passive черги

---

## Технологічний стек

- **Backend**: Python 3 + asyncio + websockets
- **Плеєр**: [mpv](https://mpv.io/) (через Unix socket IPC)
- **YouTube**: [yt-dlp](https://github.com/yt-dlp/yt-dlp)
- **MPRIS**: `pydbus` + GLib
- **Frontend**: Чистий HTML + CSS + JavaScript (односторінковий веб-інтерфейс)
- **Метадані**: `mutagen` (для локальних MP3)

## Встановлення та запуск

1. **Клонуй репозиторій**

2. **Запусти сервер**

```bash
python3 main.py
```

Сервер стартує на `ws://localhost:8765` і відкриває веб-інтерфейс.

3. **Відкрий веб-інтерфейс**

Відкрий у браузері `index.html` (ws://localhost:8765).

4. **Додай в автозапуск** (рекомендовано)

Створи systemd user unit (`~/.config/systemd/user/adv-ws-player.service`).

## Як користуватися

### Додавання треків

- **Play** → встав URL (YouTube або прямий шлях до `.mp3`) → **Додати**
- **Playlist** → встав посилання на YouTube-плейлист → додасться в **Passive Queue**

### Керування

- Кнопки в веб-інтерфейсі: Play/Pause, Next, Stop
- Підтримка MPRIS: можна керувати через KDE Connect, media keys, тощо.

### Логи

- **Actions Log** — показує всі команди (Next, PlayPause, Stop тощо)
- **Response Log** — статус відтворення та режим (active/passive)

Це не просто дебаг — це observability для розуміння поведінки сервера та інших клієнтів.

---

## Архітектура

- `active_queue` — високопріоритетна черга (грається першою)
- `passive_queue` — фонова черга (використовується, коли active порожня)
- При закінченні Active автоматично переходить у Passive
- MPRIS-інтерфейс дозволяє іншим програмам бачити поточний трек і керувати плеєром
